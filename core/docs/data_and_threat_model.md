# Data, threat model and evaluation protocol

## 1. Role of Layer 3

| Layer | Responsibility |
|---|---|
| Layer 1 | Signatures, sequence numbers, replay and storage integrity (provenance) |
| Layer 2 | Alignment, quality handling, feature windows |
| **Layer 3** | **Score how plausible each observation is, calibrate the score, raise alerts** |
| Layer 4 | Trust state, quarantine, imputation, audit log |

Layer 3 targets *valid-signature* false data: values that pass Layer 1 because the source or its credentials are
compromised. An alert is evidence for investigation, not proof of malicious intent.

## 2. Dataset

WegenerNet Level 2 v8.0 (release 2025.1), half-hourly gridded data, Feldbach region (Austria), University of Graz.
DOI [10.25364/WEGC/WPS8.0-2025.1](https://doi.org/10.25364/WEGC/WPS8.0-2025.1), CC BY 4.0.

| Property | Value |
|---|---|
| Files | 24 monthly NetCDF files, January 2023 – December 2024 (~9.15 GiB) |
| Grid | 163 × 234 cells, 100 m spacing, UTM 33N (EPSG:32633) |
| Time step | 30 min, UTC; timestamps mark interval **ends** (`time_bnds` checked) |
| Steps | 17,520 (2023) + 17,568 (2024) |

| Variable | Source field | Unit used | Quality field |
|---|---|---|---|
| Temperature | `T_z300m_HHM` (K, reference altitude 300 m) | °C (K − 273.15) | `Flagged_T` |
| Relative humidity | `RH_HHM` | % | `Flagged_RH` |
| Rain | `Precip_HHS` (accumulation per half hour) | mm / 30 min | `Flagged_Precip` |

**Virtual streams.** Every 15th cell (1.5 km spacing, 8-cell margin) is a candidate site. A site is kept if all
three variables are finite and unflagged for at least 95 % of the training period. This gives **162 sites, i.e.
486 streams**. Grid cells are interpolated products, not independent sensors, so neighbouring cells are strongly
related.

**Quality.** `Flagged_*` gives the percentage of flagged source data (fill value 101 → missing). Only values with
flag 0 are used to fit and calibrate. At scoring time every value is scored, and a quality mask is kept for
reporting. About 90 % of rain intervals are dry, and dry runs are never treated as freeze evidence. Humidity at
saturation (~100 %) may stay constant without being suspicious.

## 3. Chronological protocol

Splits are by interval start; no data crosses a boundary.

| Period | Use |
|---|---|
| Jan–Aug 2023 | Fit the feature extractor; sample training rows (nominal + synthetic attacks) |
| Sep–Oct 2023 | Calibration: nominal score distribution per variable |
| Nov–Dec 2023 | Alert-rule selection (nominal + attacked replays), then freeze |
| 2024 | Evaluation only: nominal (false alarms) and two attack seeds (91000, 191000) |

Replays use 14-day episodes (672 steps). All detector state resets at each episode, and the first 48 steps (one
day) are warm-up and never alert. Every feature uses only current and past values.

## 4. Threat model

**Attacker capability.** The attacker controls the reported values of chosen streams over a chosen interval, with a
valid signature. The attacker knows the current value, the causal past and training-period summary statistics.
The attacker cannot alter the evaluator's labels or the clean reference copy.

**Two scopes:**
1. *Local:* one site or a small neighbourhood. The other sites remain trustworthy references.
2. *Coordinated:* a contiguous patch (up to 6 km radius) or several variables at once. This weakens the
   neighbour comparison.

**Out of scope for Layer 3:** signature failures, replay, sequence gaps and storage tampering (Layer 1). Layer 3
may notice their statistical effects but does not claim cryptographic detection.

**Leakage controls.**
- The detector only sees attacked values. Labels and clean values are used only to sample training rows and to score.
- Labels mark only points whose value **actually** changed. For example, scaling zero rain changes nothing and is
  not labelled.
- Quality flags are left untouched by attacks.
- Fitting, calibration and selection never read 2024.
- The `pattern`, `mimicry` and `multivariate` families are withheld from training. They appear only in selection
  and evaluation.

## 5. Synthetic attack families

Generated by `core/detection/attacks.py` from `config/detector.yaml` (`attacks`). Each 14-day episode receives one
non-overlapping attack per family, placed at a random site and time after warm-up. Durations are 6 h, 24 h or 48 h;
a spike lasts 1–4 steps. Amplitudes are ±0.5–4 °C or ±5–20 % RH for development, and ±0.75–3 °C or ±7.5–15 % RH
for 2024 (sizes not used in training, but inside the training range). After an attack, humidity is clipped to [0, 100] and rain to ≥ 0, except for
`invalid_range`.

| Family | Manipulation |
|---|---|
| `bias` | Constant offset |
| `drift` | Offset ramping linearly from 0 to the amplitude |
| `spike` | Short offset of 1–4 steps |
| `freeze` | Last value repeated |
| `noise` | Added Gaussian noise |
| `flatten` | Deviations shrunk towards the recent 6-step mean (hides variability) |
| `rain_scale` | Rain multiplied by 0, 0.5 or 2 during a wet interval |
| `pattern` | Offset modulated by a daily cycle |
| `mimicry` | Replaced by a plausible random process using training mean/std |
| `patch` | Same offset on every site within 1.5, 3 or 6 km |
| `multivariate` | Temperature and humidity shifted together, following the training T/RH relationship |
| `invalid_range` | Humidity pushed outside 0–100 % |

## 6. Metrics

- **Point metrics** over (time, site, variable), with no point-adjustment: a long attack counts every missed point.
  Precision = TP / (TP + FP). Recall = TP / all changed eligible points (unscored points count as misses).
- **False-alert episodes per stream-day:** runs of consecutive false alerts on nominal data, counted once, per 48
  scored steps. The alert budget is ≤ 0.05.
- **Coverage:** the share of eligible points that received a score (required ≥ 95 %).
- **Event metrics:** whether an attack was detected at all, and the delay to the first alert (in steps × 30 min).
- **Per variable and per attack family:** `results/variables_2024.csv`, `results/families_2024.csv`.
